# Demo and submission plan

## The story

“A small idea changes the world—and the community can see exactly why.”

Do not begin with an architecture slide. Start with a real contribution, the theme map and the city consequence.

## Suggested 2:45 storyboard

| Time | Footage | Proof |
| --- | --- | --- |
| 0:00–0:15 | Real Twitch !idea message and moving theme map | It is connected and understandable |
| 0:15–0:40 | Different suggestions, including a small wildcard | Viewers contribute beyond preset answers |
| 0:40–1:00 | Host selects a theme, checks sources, approves | Human control and attribution |
| 1:00–1:25 | City runs and overload becomes visible | A tangible consequence |
| 1:25–1:55 | New discharge idea, revised blueprint, same seed | Audience learning changes the result |
| 1:55–2:15 | Export/history, read-only stage, pause | Reusability and engineering depth |
| 2:15–2:35 | Actual Codex work and a test/fix | Required tool use with evidence |
| 2:35–2:45 | Return to the city and product promise | Clear final impression |

If compressing the two storms, label time compression. Do not silently use demo fixtures in footage claimed as live. If using local grouping, call it local grouping; show embeddings/model generation only after a real successful configuration test.

## Recording plan

Use your own channel and original assets. Ask participating viewers for recording/display permission. Turn off notifications and hide credentials. Capture the actual app, Twitch chat and OBS output. Use original or properly licensed audio; this package includes no audio assets.

## Submission checklist

- Repository contains source, frontend, fixtures, tests and instructions.
- Fresh install/rehearsal works on another machine with Node 24.
- Actual live Twitch integration recorded.
- Video includes actual Codex-assisted development evidence.
- Video under three minutes and accessible to judges on YouTube.
- Description distinguishes local behavior, optional AI and future work.
- Actual primary Codex session ID is supplied; never invent one.
- All required Devpost fields and team details are complete.
- Judges have free testing access and valid repository access.
- All links are checked in a signed-out/private browser.
- Submission is actually submitted, not only saved as a draft.

## Rubric evidence

Innovation: the suggestion-to-playable-revision loop. Impact: creators can repeat a participatory segment. Implementation: deterministic simulation, source validation, state recovery and Twitch ingestion. Design: clear phases, readable stage and a visible outcome.

No official rule awards extra points merely for using more services or touching all suggested directions. Do not promise a guaranteed win.

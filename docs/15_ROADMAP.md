# Roadmap with completion gates

## Stage 1: trusted prototype

Complete browser and OBS QA, real Twitch rehearsal, model configuration testing if used, accessibility fixes and a polished video. Gate: a new operator can run the demo and a real community can finish a creation loop.

## Stage 2: stronger contribution intelligence

Add host rename/merge, an explicit collection window, multilingual evaluations, dynamic topic discovery and explainable cluster changes. Gate: a labeled evaluation shows the new method improves contribution fidelity without swallowing wildcard ideas.

## Stage 3: richer creation grammar

Introduce typed connections, validated resource-flow graphs, per-module source IDs, compatible objectives and an editor preview. Gate: invalid or impossible designs are rejected with clear reasons; two original scenarios work through the same engine.

## Stage 4: creator collaboration

Add two consenting channels with complementary creative roles, separate identity/origin handling and a shared artifact. Gate: tested with two real broadcasters, not only simulated second-channel input.

## Stage 5: hosted product

Implement user accounts, tenant isolation, encrypted credentials, appropriate cloud-bot transport/grants, databases, consent/retention flows and monitoring. Gate: an operational/security review plus successful repeated creator pilots.

## Stage 6: commercial offering

Add billing only after demand is established. Gate: repeat use and actual willingness to pay; avoid expanding a feature list without a customer.

These stages are future work. The delivered source implements a local one-scenario prototype and its optional adapters. It is not a scaffold that secretly contains the entire future platform.
